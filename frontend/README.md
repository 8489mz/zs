# zsystems react frontend

واجهة React + TypeScript حديثة للنظام، مبنية على feature-based architecture مع React Router وTanStack Query وZustand.

## التشغيل
```bash
npm ci
npm run dev
```

## البناء
```bash
npm run build
```

## فحوص الواجهة
```bash
npm run qa
```

## التحقق من نسخة الواجهة المنشورة (بعد كل نشر)
- معرّف البناء `__APP_BUILD_ID__` هو الـ commit المنشور (git short SHA)، ويظهر في صفحة مبيعات الفان وفي رابط الـ service worker (`/sw.js?v=<sha>`) — قارنه مع الـ HEAD المنشور قبل الحكم على أي إصلاح.
- تحديث قوي (Ctrl+F5) لا يمسح Cache Storage ولا يُسقِط الـ service worker القديم: جرّب دائماً على ملف تعريف نظيف أو نافذة تصفح خفي، أو ألغِ تسجيل الـ service worker وامسح بيانات الموقع (Application → Clear site data) ثم أعد التحميل.
- بانر التحديث يظهر فقط عند وجود worker جديد بانتظار التفعيل، ولا يفرض نفسه أبداً أثناء الوردية — التفعيل يتم فقط بضغطة المستخدم على «تحديث الآن».

## فحص الأنواع محليًا: CI فقط (قرار 2026-11-18)

- سكربت `typecheck` في `frontend/package.json` هو `tsc -b` بدون `NODE_OPTIONS`.
- CI يرفع الذاكرة إلى 4 غيغابايت (`NODE_OPTIONS=--max-old-space-size=4096` في `ci.yml` و`ci-full.yml` و`deploy-oracle.yml`) لأن الذاكرة الافتراضية (~2 غيغابايت) لا تكفي ويفشل الفحص بـ `JavaScript heap out of memory` (exit 134).
- على جهاز التطوير الافتراضي (VM) هنا لا يمكن إثبات التشغيل المحلي: الذاكرة الكلية 8 غيغابايت والمتاح لحظة القياس 2026-11-18 نحو 1.6 غيغابايت فقط (الحر ~0.2 غيغابايت، والـ swap مستخدم أصلًا)، أي أقل من نصف الـ 4 غيغابايت التي يحتاجها الفحص؛ ومحاولة التشغيل بهذا الحد تخاطر بأن يقتل نظام التشغيل عمليات أخرى لنقص الذاكرة (سبق أن قتل نقص الذاكرة عمليات أثناء تشغيل عدة وكلاء معًا). الفشل بالذاكرة الافتراضية مثبَت أصلًا 3 مرات (exit 134).
- القرار: يبقى فحص أنواع الواجهة على CI فقط — فحص `frontend-fast` في CI هو الإثبات، ولا تُضاف `NODE_OPTIONS` إلى سكربتَي `typecheck` و`build` دون إثبات محلي، لأن إضافة غير مثبَتة تبيع ادعاء تشغيل محلي بلا دليل.
- إعادة النظر: عندما تتوفر 4 غيغابايت حرة على الجهاز (أو على جهاز تطوير)، أضف الحد المطابق لـ CI إلى سكربتَي `typecheck` و`build` وأثبت `npm run typecheck` محليًا بصفر أخطاء، ثم يُستبدل هذا القرار وبند `ARCHITECTURE_INVARIANTS.md` الخاص به.
- لا يُغيَّر أي كود في الواجهة بسبب حد الذاكرة هذا — الحد حدّ تشغيل، وليس عيبًا في الكود.
